## 3. Real defects found AND fixed this pass (fail-then-pass verified)

Two money-path bugs of the **same class**: since **F148** made credit notes and vendor credits
entity-scoped (the INSERT stores `entity_id = req.entityId || null`), but their token-less 5-second
duplicate pre-checks still passed a hardcoded `null`. Under an active entity the pre-check scoped to
`null`, never matched the just-inserted row, and a token-less `<5s` double-submit created a
**duplicate credit note / vendor credit** — double-contra'ing that entity's revenue/AP. This is the
exact bug already fixed for `sales_receipts` and `payments_received`; these two were missed, and the
code comments still claimed "user-scoped (no entity_id)."

| Route | Before (HEAD) | After fix |
|---|---|---|
| `POST /api/credit-notes` | token-less <5s dup → **2 rows** (`verify-c1-credit-notes` E2 FAIL, 11/1) | **12 / 0** |
| `POST /api/vendor-credits` | token-less <5s dup → **2 rows** (`verify-c1-vendor-credits` E2 FAIL, 11/1) | **12 / 0** |

**Fix:** scope each pre-check to `req.entityId || null` to match the insert (one line each), mirroring
`sales_receipts`. Rule 13 class sweep of all `findRecentDuplicate` call sites confirms these were the
**only** two remaining instances (every other null-scoped pre-check is on a table whose INSERT does
not store `entity_id`, so no mismatch).

**Severity:** the client always sends an idempotency token, so the durable index normally catches it;
this is the token-less / direct-API path. Real, but not a routine-UI double-charge.

## 4. Not defects — harness test-debt (no product impact)

A class of older regression harnesses FATAL on seed-debt, not app bugs: they seed rows with
`entity_id = NULL`, which the **later** F150 constraint `chk_<table>_entity_nn` now correctly rejects
(`verify-c1-invoice-payments`, `verify-f26-receipt`, the `verify-f137-*` report family). Identical to
the seed-debt already fixed once in `verify-f139`. Some also hang on the thrown error rather than
exiting (F83 harness-cleanup debt), which is why they read as "slow/timeout." **The product enforces
the constraint correctly; the seeds predate it.**
