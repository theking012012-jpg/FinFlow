Security

Last updated: September 2026

We know your financial data is sensitive. Security is built into how FinFlow is designed and operated. This page summarises the measures we take.

Encryption

All traffic to and from FinFlow is encrypted in transit with TLS. Sensitive credentials — including the access tokens for any bank, payment, or accounting integration you connect — are encrypted at rest using authenticated AES-256-GCM encryption, and are never exposed back to the browser or written to logs.

Authentication & access

Passwords are stored only as salted one-way hashes, never in plain text. Sessions are server-side and regenerate on login. Password-reset links are single-use and time-limited. Role-based access control (Owner, Admin, Accountant, Viewer) governs what each user can see and do, and access is enforced per business entity.

Data isolation

Every record is scoped to its owning account and business entity, so one business's data is never visible to another. Connected integrations are scoped per entity — each business links its own accounts.

Read-only by default

Third-party connections pull data for display only. Nothing from an external provider is written into your books automatically; importing is always a separate, explicitly approved step, with duplicate-safe (idempotent) processing so the same transaction is never booked twice.

Audit trail

Changes to your books are recorded in an append-only audit trail that attributes each change to the user (or accountant) who made it, giving you a durable history for review and compliance.

Infrastructure

FinFlow runs on managed cloud infrastructure with encrypted, regularly-backed-up databases and restricted operational access. Payment processing is handled by PCI-compliant providers; we do not store full card numbers.

Reporting a vulnerability

If you believe you've found a security issue, please email security@finflow.io. We appreciate responsible disclosure and will respond promptly.
