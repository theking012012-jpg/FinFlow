## Deferred — properly, not skipped (need your call / a dedicated pass)

- **L3 — CSP `unsafe-inline`.** Cannot be removed mechanically: `index.html` has ~28 inline `<script>`
  blocks, so dropping `'unsafe-inline'` from `script-src` would dead-break the app. The correct fix is a
  nonce-based CSP (server stamps a per-response nonce; every inline script gets `nonce="…"`). That's a
  real, self-contained project — worth doing, but not a blind batch edit.
- **L5 — dead-code shadowing removal (F92).** Removing the ~23 dead app-main copies is a structural sweep
  with real regression risk; your own plan puts it post-launch. Runtime winners are correct today.
- **L7 — status-vocabulary CHECK constraints (F79).** A schema change against live data (your Rule 8,
  owner-gated). Statuses live in JSONB and vocabularies differ per table; a wrong constraint would REJECT
  valid writes and break production. Safe path: run your existing `tools/f79-status-inventory.js` to
  enumerate the real status values in production first, then we write a `NOT VALID` CHECK per table from
  that ground truth. I did **not** ship a guessed migration.
