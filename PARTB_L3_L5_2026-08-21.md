## ⛔ L3 — CSP nonce pass (remove `script-src 'unsafe-inline'`): NOT FEASIBLE as a nonce pass

**The blocker (measured):** the app has **623 inline event handlers** (`onclick=`, `onchange=`, …) across
the served HTML — **466 in `index.html` alone**, plus admin (53), accountant-client (46), etc.

CSP nonces authorize inline `<script>` **blocks**, but they do **NOT** cover inline event-handler
attributes — and adding a nonce to `script-src` *disables* `'unsafe-inline'` (CSP2 rule). So the moment you
nonce the scripts to drop `'unsafe-inline'`, **all 623 inline handlers stop firing** and the app's
interactivity dies.

**What L3 actually requires:** migrating every one of those 623 handlers from inline attributes to
`addEventListener` wiring, across every HTML file and thousands of DOM elements — then adding the nonce
middleware + per-request injection. That's a scoped refactor project (days), not a batch edit, and it
carries real regression risk on a money app. **I did not ship a half-version, because a partial nonce
change would break the live app.**

**Safe paths forward (your call):**
1. **Leave `'unsafe-inline'`** and accept it (the rest of your CSP is already tight — `frame-ancestors
   'none'`, `object-src 'none'`, `base-uri 'self'`). Pragmatic; most inline-handler SPAs live here.
2. **Do the handler migration** as its own project — I can start with one page (e.g. `admin.html`, 53
   handlers) as a verified proof-of-concept, then roll through the rest page by page.
